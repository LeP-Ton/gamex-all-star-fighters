# 架构与扩展指南

本文件描述当前“路人甲 VS 李铁”垂直切片。完整三 Boss 闯关、通关后自由挑战、Boss 连战尚未实现，不能由首场胜利推导为完整通关。需求进度与验收以[需求入口](../.agentdocs/workflow/REQ-20261104135500-首场格斗垂直切片/README.md)为准。

## 分层与数据流

```text
键盘输入 / 界面操作
        ↓
GameView 的固定步长累加器（每次 1/60 秒）
        ↓
CombatEngine.step(InputFrame)
  ├─ 状态、输入缓冲、招式时序与资源
  ├─ BossAI 的当前局面评分
  ├─ SkillSystem 的技能执行器
  └─ geometry 的攻击 / 受击 / 身体碰撞
        ↓
CombatSnapshot + 本步 CombatEvent
        ↓
Phaser 人物帧、场景、特效与音效 + HTML 界面
        ↓
单场结算 → RecordManager → LocalStorage
```

`src/core/` 不导入 Phaser、DOM 或音频 API，可以在 Vitest 中无图形运行。Phaser 负责资源加载、画面、声音与输入适配；代码没有接入大语言模型作为游戏 AI。

| 文件 | 职责 |
|---|---|
| `src/core/types.ts` | 输入、角色状态、快照、危险物和事件契约 |
| `src/core/CombatEngine.ts` | 固定一步战斗推进、状态切换、输入缓存、碰撞结算、计时与胜负 |
| `src/core/geometry.ts` | 世界边界、地面、矩形及圆形碰撞工具 |
| `src/core/BossAI.ts` | 距离、资源、血量和冷却参与的技能评分 |
| `src/core/SkillSystem.ts` | 四种 Boss 技能执行器及其上下文 |
| `src/data/moves.ts` | 普攻/重击/空中/必杀帧数据、角色注册与 Boss 技能定义 |
| `src/render/GameView.ts` | Phaser 生命周期、输入、固定步长、事件消费、特效和调试显示 |
| `src/render/AnimationController.ts` | 由角色状态和状态帧选择原画帧 |
| `src/ui/RecordManager.ts` | 玩家姓名、声音设置、单场最佳与最近成绩 |
| `scripts/generate-audio.mjs` | 原创合成音效生成，不下载第三方音频 |

当前采用少量清晰模块，没有为每个建议类名都创建空壳。状态机与命中系统仍在 `CombatEngine` 内；扩展到多角色后可按稳定职责继续拆分。

## 时间、输入与状态

- `CombatEngine.step(input)` 每调用一次代表一个 60 Hz 时钟步。`GameView` 按累积时间调用，单次渲染最多追赶 6 步；长时间挂起后的积压被丢弃，恢复时不会瞬间推进数秒攻击。
- 输入包含持续方向/防御与动作按键。动作输入按“刚按下”进入 8 帧缓存，执行后消费；长按不自动重复触发新攻击。
- 普攻命中后才开放配置的取消窗口，可接下一段普通攻击、重攻击、闪避或必杀。空挥不享有命中取消。
- 每个招式显式指定 `startup`、`active`、`recovery`、伤害、范围、击退、硬直、能量和取消起止帧。参数单位为逻辑帧，60 帧约为 1 秒。
- 菜单暂停冻结战斗与计时；命中停顿和精准闪避慢动作由核心独立处理。当前比赛计时包含命中停顿和慢动作持续的时间。
- `snapshot()` 返回复制数据；`events` 只表示最近一次 `step` 产生的事件。渲染必须逐步消费事件，不能只消费一轮追帧后的最后一个快照，否则会漏掉命中音效。

## 技能与 Boss 扩展

新增招式时，在 `MOVES` 中增加配置，并为角色指定可用招式；不要直接在渲染代码中扣除生命或生成有效攻击。不同招式可以共用命中结算，伤害和视觉均由同一次核心事件驱动。

新增 Boss 的实施顺序：

1. 通过首场美术和手感门槛，确定新 Boss 的独立机制及可反制窗口。
2. 在角色与 Boss 注册数据中增加生命、移动、场景、技能等定义。
3. 在 `BOSS_SKILLS` 添加时长、冷却、消耗、提示；在 `SKILL_HANDLERS` 注册执行器。执行器通过上下文生成危险物、发出事件或更新提示。
4. 为该 Boss 提供 AI 评分策略，仅读取当前局面，设置高伤害前摇和结束后反击窗口。
5. 接入原创动画清单、场景与音效，然后用固定种子和明确输入验证机制。

当前 `createFighter`、`chooseBossSkill` 及部分技能参数仍专门面向首场，注册表不是已经完成的通用插件框架。后续需把 Boss 定义作为构造参数注入，并将执行器中的专属时间点外提为技能时间线；不需要重写基础碰撞、输入缓冲或存档系统。许家印的召唤单位与控制免疫、释永信的能量封锁需新增领域数据与规则，不能通过更换名称复制首场技能。

## 美术导入与音效

当前资源路径为：

- `public/assets/stadium.png`：首场夜间球场。
- `public/assets/player-sheet.png`、`boss-sheet.png`：各 6 列 × 4 行，共 24 个姿态格。
- `public/assets/audio/*.wav`：12 个合成音效，由 Phaser 音频系统加载。

渲染按图片实际尺寸等分切帧，使用统一脚底基点和左右镜像。`AnimationController` 仅读取状态和状态帧，不触发伤害。部分动作目前仅有单姿态或复用帧，24 格资源必须标为原创 AI 动画初稿，尚不满足任务书的完整正式动画要求。

后续正式动画应采用显式 Atlas 帧矩形、每帧脚底原点、持续帧与关键动作标记，不应依赖 AI 自动生成的整张 Sprite Sheet 恰好网格对齐。每个招式的命中帧需要与伸展姿态逐项对齐；受击、倒地、起身、胜利和失败都需要独立有效帧。画面预警、尘土、残影等程序特效可保留，但不能代替人物动作原画。

音效在消费 `CombatEvent` 时播放；同一伤害事件驱动声音、火花和震动。浏览器通常需要用户操作后才能播放声音，音效开关保存在本地。

## 本地存档

存储键为 `gamex-all-star-fighters:v1`，数据包含版本、姓名、首次命名 registered 标识、声音设置、最佳单场成绩与最近 30 条历史。姓名去除首尾空白并按 Unicode 码点截取 12 字，空名恢复为“路人甲”。

`BattleRecord` 保存日期、用时、最高连击、剩余生命、受击次数、胜负与 `story`/`training` 模式。仅 `story` 胜利参与最佳成绩比较，训练成绩可留在历史中。首场成功不会写入完整通关或模式解锁标记。

读取时验证字段类型、日期、有限非负数字及整数计数，损坏 JSON 或未知版本回到默认值；存储被拒绝或空间不足时保持会话内状态，不中断游戏。此处没有联网、云同步或跨设备排行榜。

## 调试与验证入口

`GameView.setDebug(true)` 显示核心快照中的攻击框、受击框、身体框与状态信息。`CombatEngine` 另提供：

- `debugSetFighter(id, patch)`：设置测试局面。
- `debugStartSkill(id)`：直接触发指定 Boss 技能。
- `getMoveData()`、`updateMove(id, patch)`：读取和临时调整起手、有效、恢复、伤害、范围；只影响本次运行，不修改源数据文件。
- 构造选项 `{ seed, training }`：种子控制 AI 随机性；训练模式使用被动 Boss、初始满能量、无超时失败，生命耗尽仍正常结算。

正式挑战仅开放判定框查看，招式参数修改和强制技能触发限自由练习；界面修改后点击“应用本场参数”。

运行 `npm test` 验证核心与存档，`npm run build` 进行 TypeScript 类型检查和生产构建。上述入口不能代替真实试玩；60 FPS 表现、动画连续性、不同浏览器兼容性及最终美术验收必须分别记录实测结果。
